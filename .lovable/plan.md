
# 품질 심화 스프린트 (Depth & Polish Sprint)

## 왜 지금 이게 필요한가

오늘 하루만 봐도 — 결재 상태 미동기화, 시공사 필터 누락, 결재라인 타사 노출, FK 충돌, 자동생성 빈 화면 — 모두 "기능은 있는데 **경계 조건(edge case)** 이 비어 있다" 는 같은 패턴입니다. 새 기능을 더 만드는 게 아니라, **이미 만든 기능 하나하나에 깊이(완결성)** 를 채워 넣는 작업이 필요합니다.

방법은 세 가지를 동시에 돌리는 겁니다.

---

## 방법 1. "기능 카드(Feature Card)" 체계 도입 — 깊이의 정의를 표준화

각 기능마다 다음 8가지를 **모두 충족해야 "완료"** 로 봅니다. 지금은 1~3번만 채우고 끝내고 있어서 4~8번에서 매번 버그가 터집니다.

```text
1. Happy path        - 정상 입력으로 결과가 나온다
2. Permission        - 역할 5종 × CRUD 가 매트릭스대로 동작
3. Scope             - 회사/프로젝트 격리가 SELECT·INSERT·UPDATE 모두에서 지켜짐
4. Empty / Loading   - 데이터 0건, 로딩 중, 네트워크 실패 UI
5. Edge inputs       - 한글 IME, 긴 텍스트, 0/음수, 첨부 없음
6. State sync        - 결재·승인·삭제 시 미러 컬럼·알림·뱃지가 한 트랜잭션에서 갱신
7. Audit             - 누가/언제/왜 변경했는지 로그
8. Rollback          - 잘못 눌렀을 때 되돌릴 수 있다 (휴지통/취소/재상신)
```

`docs/feature-cards/{기능}.md` 한 장으로 관리하고, **PR 머지 전 이 체크리스트를 통과해야 함**.

---

## 방법 2. "Top 12 코어 기능"만 골라 한 사이클에 깊이 채우기

전체 100여 개 화면을 동시에 손대면 또 표면만 긁고 끝납니다. 사고 위험·법적 의무·매일 사용 빈도로 가중치를 매겨 **12개만** 골라서 위 8체크리스트를 100% 채웁니다.

| # | 기능 | 현재 약점 |
|---|------|----------|
| 1 | 위험성평가 회차/항목 | 시공사 필터, 빈 결과, 캐시 오염 |
| 2 | 작업계획서 | 첨부 누락, 차량계 등 누락 타입 |
| 3 | 작업허가서 | 결재 미러, 작업자 매핑 |
| 4 | TBM | 다중 서명 충돌, QR 연동 |
| 5 | 결재 (통합) | 상태 미러, 타사 결재자, 위임/반려 사유 |
| 6 | 사고 보고 | 법정 기한 알림, 첨부 |
| 7 | 비상대피훈련 | 주기 알림, 참여자 매핑 |
| 8 | 산업안전보건관리비 | 검증, 증빙 첨부 |
| 9 | 근로자 출입/QR | 오프라인 큐, 중복 출근 |
| 10 | 교육 매핑 | 자동 할당 후 만료 알림 |
| 11 | 점검/시정조치 | 만기 To-Do 연동 |
| 12 | 작업중지권 | 사진 필수, 즉시 알림 |

각 기능당 **반나절~1일** 작업 (오늘처럼 작은 픽스 묶음). 12개 × 1일 = **약 12 영업일 = 2.5주**.

## 방법 3. "자동 회귀 그물(Regression Net)" 구축 — 두 번 같은 버그 안 나게

같은 버그가 반복되는 진짜 원인은 **수동 검증** 이기 때문입니다. 한 번 잡은 버그를 자동 테스트로 못박아 둡니다.

추가할 것:
1. **`/admin/system-test`** 시나리오 확장: 12개 코어 기능 각각 1개 E2E (Playwright) — 매 배포 전 자동 실행.
2. **권한 행렬 vitest**: 5역할 × 12기능 × 4액션 = 240 케이스, `useProjectAccess.can*` 단위 테스트.
3. **데이터 정합성 RPC**: `audit_data_consistency()` 를 cron 으로 매일 실행 → 위반 시 마스터에게 알림.
4. **결재 미러 트리거 일관성 테스트**: 도큐먼트 5종에 대해 "결재완료 → status='승인완료' & 알림 발송 & 감사로그 1건" 을 SQL 로 검증.
5. **에러 silent fail 정적 검사**: ESLint 룰로 `catch {}` 빈 블록·`toast` 없는 catch 차단.

## 사이클 (반복 가능)

```text
주차 1   기능 카드 템플릿 확정 + 회귀 그물(테스트 인프라) 구축
주차 2-3 코어 기능 12개 × 8체크리스트 (하루 1개 진도)
주차 4   회귀 테스트 전체 실행 + 발견 결함 정리 + 다음 12개 후보 선정
```

이걸 **분기마다 1사이클** 돌리면, 6개월 뒤에는 모든 핵심 화면이 8체크리스트를 통과하는 상태가 됩니다.
