# 사용 설명서 개편 — 작업 지시서

> 대상 파일: `src/pages/Manual.tsx` (공개 라우트 `/manual`)
> 사용법: 아래 프롬프트를 단계별로 커서에 붙여넣습니다.

---

## 왜 고치는가

메뉴얼이 `Manual.tsx` 안에 **하드코딩된 정적 배열**입니다 (`SECTIONS` 8개, `FAQS` 5개). 시스템이 8개 메뉴에서 **52개**로 커지는 동안 이 배열만 초기 상태로 남았습니다.

### 검증된 오류

| 메뉴얼 현재 | 실제 (SSOT) |
|---|---|
| "3x3 매트릭스(**빈도×강도**)" | 3x3은 맞음. 축은 **가능성 × 중대성** (`src/lib/riskGrade.ts` `DEFAULT_LABELS`) |
| 등급 "**저/중/고**" | **상/중/하** (`riskGrade.ts` `type RiskGrade`) |
| 근로자 입장 = **QR 스캔만** | **GPS 출퇴근**이 주 경로 (`WorkerDailyHome.tsx` → RPC `worker_gps_daily_lifecycle`) |
| "좌측 메뉴 … 진입" | 모바일은 하단 탭(`mobileTabsForBucket`), 좌측 메뉴는 데스크톱 전용 |
| 역할 = 관리자 / 근로자 2종 | 실제 7종 (`roleLabelKo`) |

"개선후(잔여) 등급" 개념도 메뉴얼에 없습니다.

### 누락된 기능 (일부)

전자결재 · 산업안전보건관리비 · 작업중지권 · 사고 관리 · 비상대피훈련 · 통합 현장 관제맵 · 구역 출입 모니터링 · 위치 추적 · 안전보건교육 · 안전관리자 선임 · 법적업무 · 협력사 안전성적표 · 건강진단 · 작업환경측정 · 화학물질/MSDS · 유해요인조사 · 현장 공지 · 검증센터 · 할 일 · 회사 관리 · 기준정보 · 권한 점검

---

## 개편 방향 (승인됨)

1. **역할별 분리** — 진입 시 역할을 고르면 자기 것만 보임
2. **근로자용은 그림 중심 1페이지** — 용어 없이 하루 흐름만
3. **관리자용은 업무 흐름 순서로** — 52개 메뉴 나열 금지
4. **용어 사전 추가**
5. **FAQ는 코드가 정의한 "막히는 지점"에서 도출** — 추측 금지

### 중요 원칙

**내용을 이 문서에서 베끼지 말고, 아래에 지정한 SSOT 파일에서 읽어서 쓸 것.** 이 문서의 요약이 틀렸을 수 있으므로 코드가 기준입니다. 문서와 코드가 다르면 **코드가 맞습니다**.

## 프롬프트 1 — 역할 분리 + 구조

```
risk-guard-express 의 사용 설명서(src/pages/Manual.tsx)를 역할별로 분리해줘.
배경은 docs/manual-revamp-prompts.md 를 먼저 읽어봐.

AGENTS.md 의 "승인 후 코딩" 원칙은 이 작업에 한해 이미 승인받았어.
다만 아래에서 "물어봐" 라고 한 지점은 반드시 확인하고 진행해.

═══ 목표 ═══
지금은 한 페이지에 관리자와 근로자 내용이 섞여 있어서, 처음 보는 사람이
자기와 무관한 설명을 계속 지나쳐야 해. 역할을 고르면 자기 것만 보이게 한다.

═══ 작업 1 · 역할 선택 게이트 ═══
/manual 진입 시 역할 3개 중 선택:

  [근로자]  [관리감독자]  [안전관리자·관리자]

- 선택은 localStorage 에 기억 (다음 방문 시 바로 해당 섹션)
- 상단에 "역할 바꾸기" 버튼 항상 노출
- /manual 은 **로그인 없이 접근 가능한 공개 라우트**야. 로그인 상태를 전제하지 마.
  단, 로그인돼 있으면 그 사람의 역할을 기본 선택으로 제안해도 좋아
  (역할 판정은 src/lib/mobileShell.ts 의 roleLabelKo / resolveMobileShellBucket 참고)

실제 역할은 7종이야 (roleLabelKo): 마스터 / 프로젝트 관리자 / 안전관리자 /
현장관리자 / 감리 / 관리감독자 / 근로자.
이걸 메뉴얼에서는 3개 묶음으로 단순화해줘:
- 근로자 → "근로자"
- 관리감독자 → "관리감독자"
- 마스터·프로젝트 관리자·안전관리자·현장관리자·감리 → "안전관리자·관리자"

═══ 작업 2 · 공통 영역 (역할 무관) ═══
역할 선택 위/아래에 남길 것:
- 검색 + 하이라이트 (지금 구조 그대로 유지 — 잘 되어 있음)
- "이 시스템은 무엇인가요" 소개 카드
- 용어 사전 (프롬프트 3에서 채움)
- 오류신고 폼 (InquiryForm — 그대로 유지)
- 인쇄/PDF 저장, "따라하기 다시 보기" 버튼 (그대로 유지)

검색은 **선택한 역할 안에서만** 검색되게 할지, 전체에서 검색할지 —
나는 전체 검색이 낫다고 보는데, 구현 전에 너 의견을 말하고 물어봐.

═══ 작업 3 · 데이터 구조 정리 ═══
지금 SECTIONS / FAQS 가 Manual.tsx 안에 하드코딩돼 있어서 시스템이 커져도
갱신이 안 됐어. 별도 파일로 분리해줘:

  src/lib/manualContent.ts

  export type ManualAudience = "worker" | "supervisor" | "admin";
  export type ManualSection = {
    id: string; audience: ManualAudience[]; title: string;
    keywords: string[]; bullets: string[];
  };
  export type ManualFaq = { q: string; a: string; audience: ManualAudience[]; keywords: string[] };
  export type ManualTerm = { term: string; plain: string };

audience 가 배열인 이유: 일부 항목은 여러 역할에 공통이야
(예: 알림, 작업중지권은 전 역할).

Manual.tsx 는 이 데이터를 읽어서 렌더만 하게 해줘.

═══ 주의 ═══
- 검색·하이라이트·오류신고 폼·인쇄는 동작이 바뀌면 안 돼
- /manual 공개 접근 유지 (로그인 강제 금지)
- 내용 채우기는 프롬프트 2·3에서 할 거야. 이 단계는 구조만.
```

## 프롬프트 2 — 내용 (역할별)

```
risk-guard-express 사용 설명서의 내용을 역할별로 채워줘.
프롬프트 1(구조 분리)이 끝난 뒤에 진행해.

═══ 원칙 ═══
내용을 내가 준 요약에서 베끼지 말고, **아래 지정한 파일을 직접 읽어서** 써줘.
요약이 틀렸을 수 있어. 코드가 기준이야.
docs/feature-cards/ 는 일부가 코드보다 오래됐으니 코드를 SSOT 로 봐.

═══ 근로자 (audience: "worker") ═══
목표: 전문용어 없이, 하루 흐름 한 페이지.

읽을 곳:
- src/pages/WorkerDailyHome.tsx — 실제 출퇴근 화면
- RPC worker_gps_daily_lifecycle (supabase/migrations/20260808020000_*.sql)
  → entry / ack / exit 3단계가 실제 흐름이야
- src/lib/mobileShell.ts mobileTabsForBucket("worker")
  → 하단 탭: 오늘 / 할 일 / 자료 / 알림 / 더보기

담을 내용:
1. 하루 흐름: 출근 → TBM 확인 → 작업 → 퇴근(무재해 확인)
2. 하단 탭 5개가 각각 뭔지 (한 줄씩)
3. GPS가 뭘 하는지 — "현장에 있으면 자동으로 출근이 찍힌다" 수준으로
4. 위험구역 경고가 뜨면 어떻게 해야 하는지
5. 작업중지권 — 근로자 권리니까 반드시 넣어줘

쓰지 말 것: 상신 / 결재선 / 공종 / 잔여위험 / 검증센터 같은 관리 용어

※ 출입이 QR 뿐이라고 쓰면 안 돼. 지금 메뉴얼의 가장 큰 오류야.
  GPS 출퇴근이 주 경로고 QR도 있어. 둘 다 설명해줘.

═══ 관리감독자 (audience: "supervisor") ═══
읽을 곳:
- src/lib/assessmentSubmitPreflight.ts — 위평 작성 주체가 관리감독자임
- docs/feature-cards/risk-assessment.md (§2 Permission)
- src/pages/AssessmentRunDetail.tsx, WorkPermitDetail.tsx

담을 내용: 위험성평가 작성 · 작업허가서 · TBM 진행 · 근로자 의견 수렴

═══ 안전관리자·관리자 (audience: "admin") ═══
목표: 52개 메뉴 나열이 아니라 **실제 업무 순서**로.

흐름: 위험성평가 → 작업계획서 → 작업허가서 → TBM → 작업 → 점검/조치 → 사고대응 → 비용정산

지금 메뉴얼에 아예 없는데 반드시 넣어야 할 것:
- 전자결재 (모든 문서가 거쳐가는 핵심인데 섹션이 없음)
- 산업안전보건관리비 (법정 서류)
- 작업중지권 / 사고 관리 / 비상대피훈련
- 위험구역·위치추적 (GPS 관련)
- 알림 설정
- 보건 영역 (건강진단 / 작업환경측정 / 화학물질 MSDS)

각 항목은 사이드바 실제 메뉴명과 맞춰줘 (src/components/AppSidebar.tsx).

═══ 위험성평가 등급 — 반드시 고칠 것 ═══
현재 메뉴얼(Manual.tsx:36)이 틀렸어:

  현재: "3x3 위험도 매트릭스(빈도×강도)로 등급 산정 (저/중/고)"
  실제: src/lib/riskGrade.ts 를 읽어봐
        - 3x3 은 맞음
        - 축은 가능성(likelihood) × 중대성(severity)  ← 빈도/강도 아님
        - 등급은 상/중/하  ← 저/중/고 아님
        - "개선후(잔여) 등급" 개념이 따로 있음 (deriveResidualGrades)

처음 보는 사람이 "저/중/고"를 찾다가 화면의 "상/중/하"를 보면 바로 막혀.
riskGrade.ts 의 DEFAULT_MATRIX 를 보고 3x3 표를 시각적으로 그려주면 더 좋아.

═══ 마무리 ═══
- bun run test 통과 확인
- 각 역할 섹션을 하나씩 작성하고 단계마다 보여줘
- 코드를 읽어보니 내 설명과 다른 부분이 있으면 반드시 알려줘
```

