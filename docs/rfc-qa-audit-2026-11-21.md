## 🔴 P0 — 실사용 기능 차단 / 데이터·API 오류 (최우선)

### 1. TBM 일지 목록 `참여 0명` · `총 참여자 0` 표시 (`HTTP 400` + 1,000행 상한)
- **현상**: `TBM 일지`(`/app/admin/tbm-logs`)에서 `오늘`·`전체 일자` 모두 카드가 **`참여 0명`**, KPI가 **`총 참여자 0`**으로 표시됨. 카드를 열어보면 `참여자 (6명)`·`참여자 (30명)` 및 실제 서명이 존재함.
- **원인 (`src/components/tbm/TbmManager.tsx:141-152`)**:
  - 프로젝트 전체 TBM 세션(여수 **816세션 / 참여 8,081건**, 청주 **245세션 / 참여 2,716건**)의 ID를 `.from('tbm_participations').select('tbm_session_id').in('tbm_session_id', ids)` 쿼리스트링에 한꺼번에 실어 보내 **HTTP 400 (URL 길이 초과)** 발생 → `parts`가 `null`이 되어 전원 `0명` 출력.
  - 세션 수가 적은 프로젝트에서도 PostgREST 기본 1,000행 상한에 잘림(`SiteReadinessChecklist.tsx:38-39`, `Companies.tsx:67`, `AssessmentRunDetail.tsx:715` 등 동일 패턴 존재).
- **제안**:
  - 서버 집계 RPC(`get_tbm_participant_counts(_project_id uuid, _session_ids uuid[])`) 또는 PostgREST embedded count(`tbm_participations(count)`) 도입 + 목록 쿼리에 일자/페이지네이션 적용.
  - `openParticipants`에서 사용하는 `safety_acknowledgements` 보정(`fillMissingTbmSignatures`)과 목록 카운트 기준 일치 여부도 함께 정리.

### 2. 과거/완료 문서 인쇄·PDF가 `"작성 주체(관리감독자)를 지정하세요"`에 막힘
- **현상**: 관리감독자 지정 의무화 이전 작성·완료·만료된 과거 문서(예: `70T크레인 작업계획서_260825`, 실DB `만료` 상태 작업계획서 **10건**, `결재진행` 위험성평가 등)에서 **`인쇄`**·**`PDF`** 클릭 시 `"작성 주체(관리감독자)를 지정하세요"` 토스트로 출력 자체가 차단됨.
- **원인**:
  - 서버 PDF 생성기(`supabase/functions/generate-pdf/index.ts:526`, `supabase/functions/generate-workplan-pdf/index.ts:212`)는 이미 `author_user_id || created_by` fallback을 지원함.
  - 반면 프론트(`src/pages/WorkPlanDetail.tsx:562-567, 616-620`, `src/pages/AssessmentRunDetail.tsx:2079-2082, 2109-2112`)가 문서 상태와 무관하게 `author_user_id` 미지정 시 인쇄/PDF를 원천 차단.
- **제안**:
  - **정책 분리**: `작성 주체(관리감독자)` 필수 검사는 **신규 작성·결재 상신 시점**에만 유지.
  - **인쇄·PDF 열람**은 `만료`·`승인완료`·`결재중`/`결재진행`·`반려`·`작업취소` 등 과거/기존 문서(`author_user_id IS NULL`)도 `created_by` fallback으로 즉시 출력 허용.
  - *협의 질문*: `작성중` 초안 문서의 미리보기 인쇄도 허용(경고 토스트/워터마크 포함)할지, 아니면 `작성중`만 차단 유지할지?

### 3. 안전점검 상세 `HTTP 400 (PGRST200)` — `project_members` ↔ `profiles` 조인 오류
- **현상**: `/app/admin/safety-inspections` 진입/상세 조회 시 매번 콘솔·네트워크에 **HTTP 400** 발생.
- **원인 (`src/pages/SafetyInspections.tsx:328`)**:
  ```ts
  supabase
    .from('project_members')
    .select('user_id, role_new, position_new, company_id, companies(name, type, parent_company_id), profiles(display_name)')
    .eq('project_id', projectId)
  ```
  `project_members`와 `profiles` 사이에 PostgREST FK 관계가 없어 `PGRST200` 실패.
- **제안**: 다른 모듈과 동일하게 `project_members` 조회 후 `user_id` 목록으로 `profiles` 별도 조회하여 병합.

### 4. 전자결재 `반려` 카운터 ↔ `반려` 탭 목록 불일치 (이미 `승인완료`된 문서 혼입)
- **현상 (2개 프로젝트 교차 확인)**:
  - 여수: 상단 KPI **`반려 3`**, 그러나 `반려` 탭에는 **17건** 노출 — 이미 재상신 후 **`승인완료`**된 `11월4주차` 및 **`결재진행`** 문서 포함.
  - 청주: 상단 KPI **`반려 2`**, 그러나 `반려` 탭에는 **3건** 노출 (승인 완료된 작업허가서 포함).
- **원인 추정**: 이전 회차 반려 사유(`이전 반려 사유`)가 남아 있는 문서를 `반려` 탭에 계속 포함시켜 KPI 카운터(현재 `반려` 상태 기준)와 괴리 발생.
- **제안**: `반려` 탭과 KPI 카운터 모두 **현재 상태가 `반려`인 문서**로 단일화하고, 과거 반려 이력은 문서 상세/타임라인 배지로만 표시.

### 5. 작업허가서 목록 전체 `상신: - · 발행 승인: -` 누락 + 상세 `작업인원 0명` vs `49명` + 복제 타임스탬프 잔존
- **현상**:
  1. `/app/admin/work-permits` 목록 카드 전체가 `📤 상신: -`, `✅ 발행 승인: -`로 표시됨(`src/pages/WorkPermits.tsx:618`), 상세에 들어가면 실제 이름(`차강찬`, `박서로`)이 정상 존재.
  2. 최신 허가서(`f28a2cbc`, 작업일 `2026-11-23`)에서 상단/TBM 배지는 `작업 인원 0명`인데 PTW 본문 표는 `작업인원: 49명`.
  3. 미래 작업일(`2026-11-23`) 허가서에 `작업완료 확인: 2026-11-19 08:15`이 찍혀 있고, `검토일(2026.11.19)`이 `담당자(시공) 상신(2026.11.20 14:29)`보다 하루 빠르게 표시됨(과거 문서 복사 시 완료/검토 타임스탬프 미초기화 또는 UTC 변환 의심).
  4. `전체 기간` 선택 상태에서 날짜 검색 결과 0건일 때 `"기간을 「전체 기간」으로 바꿔 보세요"` 모순 안내 노출.
- **제안**: 목록 작성자/승인자 이름 매핑 수정, 허가서 복제 시 `completed_at`/검토일 필드 초기화, 작업인원 배지/본문 기준 일치화.
